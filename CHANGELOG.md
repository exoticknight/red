# Changelog

## 0.1.2

- Clarify knowledge ownership, durable rationale, reader-task verification, and replacement of existing knowledge in the RED Skill.
- Add scenarios for package installation guides, package renaming, and retiring design records.
- Refresh the repository README with RED visuals and a quick start.

## 0.1.1

- Expand the npm and PyPI package pages with the RED model, Skill and CLI roles, installation, first-use examples, maintenance commands, and documentation links.
- Add the English edition of the RED paper and link the two language editions from the paper and package pages.
- Verify existing npm releases through the exact version endpoint when retrying publication.

## 0.1.0

- Define RED Protocol 1 and its Research, Evolve, and Document states.
- Allow clear, authorized changes to enter Evolve without Research; use Research for decision-blocking unknowns.
- Add separate human or project-authorized checkpoints for Research-to-Evolve and Evolve-to-Document transitions.
- Add one host-neutral RED Skill with engineering, adoption, inspection, artifact, and fallback modes.
- Add equivalent Node and Python CLIs.
- Generate unpadded, unbounded positive integers for artifact identifiers while accepting the legacy four-digit form.
- Add safe Skill lifecycle and lightweight `AGENTS.md`/`RED.md` installation.
- Let each project choose whether Research and Evolve live in Git, local files, or an external collaboration system.
- Keep one tracked Skill source and generate package bundles and local self-hosting installations from it.
- Add shared cross-language conformance fixtures.
- Add tag-driven npm, PyPI, plugin, Skill, and GitHub release automation.
